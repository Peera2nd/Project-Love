# 04 — Mistakes and Prevention Registry

Read before edits. Never repeat a recorded failure. Immediately record encountered failures, corrected misunderstandings, and fixed issues with cause and prevention. Unknown causes must remain explicitly unknown.

## Guardrails

| ID | Risk | Mandatory prevention |
| --- | --- | --- |
| GR-001 | Hardcoded content | Keep names, dialogue, stats, item prices, skill labels and story flags in data. Systems remain setting-agnostic. |
| GR-002 | Editor APIs in builds | Put UnityEditor code in `Scripts/Editor/` and its Editor-only assembly, or guard it with `UNITY_EDITOR`. |
| GR-003 | Legacy input | Use Input System `1.20.0` / InputAction. Do not assume legacy `UnityEngine.Input` is enabled. |
| GR-004 | Legacy UI text | Use `TMPro.TextMeshProUGUI` for runtime UI text. |
| GR-005 | Broken typewriter/rich text/Thai marks | Set the full TMP text and control `maxVisibleCharacters`; do not reveal via Substring. Verify Thai marks, wrapping, and rich text with actual fonts. TMP alone is not a complete Thai-support guarantee. |
| GR-006 | Broken Unity GUID references | Move/rename assets and their `.meta` files together; preserve existing GUIDs. |
| GR-007 | Runtime mutation of source assets | ScriptableObjects hold static definitions; separate serializable runtime state and JSON saves. |
| GR-008 | Lost Editor edits | For asset changes, integrate serialized editing/Undo as appropriate, call `EditorUtility.SetDirty(target)` and `AssetDatabase.SaveAssets()`, and preserve prefab editing semantics. |
| GR-009 | Movement scope creep | No walking-map exploration. Use fixed isometric room/scene hotspots and VN overlays; phase-driven pose/position swaps do not require walking movement. |
| GR-010 | Wrong document language | Backend specs/tasks/handoffs/logs/rules: concise English. User interaction and narrative/character documents: Thai. Preserve identifiers and useful existing English machine-facing prompts. |
| GR-011 | Reverting duration or keeping punitive old pacing | Full playthrough: 30 configurable days. Old 14-day references are historical only. Revisit event timing and workload; allow gradual bonding and recovery from ordinary mistakes. Exact balance remains unverified until tested. |
| GR-012 | Code-only or Play-only authoring | Routine writing/balance/art/layout must have discoverable Thai-facing tools, serialized sources, Undo/Save and safe previews. Use persistent UI prefabs; runtime binds values without rebuilding fixed views or overriding authored layout. Initial migration must preserve later artist edits. Feature acceptance includes the real authoring workflow. Owner decision: Session 044. |
| GR-013 | Excessive testing while missing visible UX defects | Match verification to changed behavior. Small Editor/UI fixes need compile/affected-window checks, not automatic full-game suites or repeated rebuilds. Existing passing tests do not establish visual readability; inspect the affected layout and state any remaining visual limits. Owner direction: Session 045. |
| GR-014 | Silent localization deferral or false adoption claim | Session 063 / AGENTS 10: preserve the baseline; next text-bearing playable/content/system version implements/adopts the [Thai/English contract](../04_Technical_And_Tools/13_Localization_Architecture_And_Adoption_Contract.md). Keep stable gameplay IDs, explicit Thai fallback and save guards. Record actual scope/evidence in its adoption register and report adoption/legacy/translation gaps to the owner; a designed contract or empty table is not runtime support. |
